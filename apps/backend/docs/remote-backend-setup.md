# Backend işletim rehberi

Bu belge kurulum, dağıtım, worker ve restore prosedürünün sahibidir. Kaynak/ortam kabulü [güncel kabul kaydında](00-FtkSaaS-yeni-sohbet-devir.md), açık işler [backlog’da](remaining-work.md), ürün davranışı [ortak iş akışlarında](../../../docs/workflows.md) tutulur. Geçmiş denemeler canlı talimat olarak burada yinelenmez.

## Eklentisiz hosted kabul komutları

Komutlar backend dizininden mevcut development projesi ve yetkili test hesaplarıyla çalışır. Sonuçlar ve açık kabul sınırları [güncel kayıttadır](00-FtkSaaS-yeni-sohbet-devir.md#s07s15-eklentisiz-hosted-kabulü--7-kasım-2026). Telefon/SMS doğrulaması V1 kapsamından çıkarılmıştır; hosted test OTP veya SMS sağlayıcı kurulumu yapılmaz.

Özel ortamda FTK_ACCEPTANCE_EMAIL, FTK_ACCEPTANCE_PASSWORD, publishable FTK_ACCEPTANCE_APIKEY ve gerçek FTK_ACCEPTANCE_ORG, FTK_ACCEPTANCE_CENTER, FTK_ACCEPTANCE_DISCIPLINE, FTK_ACCEPTANCE_SESSION girdileri sağlanır. Pro hazırlık testi iki organization şablon alanına geçici öneri ekler ve önceki değerleri yeni sürümle geri yükler; immutable test geçmişi kalır. Concurrent yazara karşı zorla geri alma yapılmaz. Grant veya anlaşma yayını oluşturmaz.

```sh
node scripts/acceptance/s10-hosted-preparations.mjs
node scripts/acceptance/s07-s15-browser.mjs
```

Playwright ayrı kurulumdan yüklenir; gerekirse FTK_PLAYWRIGHT_MODULE modül yolu ve FTK_PLAYWRIGHT_CHROMIUM kurulu headless Chromium executable'ı belirtilir. Kullanıcının11 Kasım kabul yöntemi: bütün tarayıcı kontrolleri önce Playwright ile denenir; yalnız Playwright ile tamamlanamayan kontrol Chrome eklentisine taşınır. Playwright runner ayrı profilde çalışır. Eklentiye geçişin somut nedeni ve doğrulanan senaryo kabul kaydında belirtilir. Ortam HTTPS_PROXY kullanıyorsa browser da kullanır; CODEX_PROXY_CERT varsa yalnız bu CA'nın SPKI fingerprint'i eklenir, genel ignoreHTTPSErrors açılmaz. Credential/provider payload/HTML/browser storage raporlanmaz; screenshot/trace/video alınmaz.

## İş takvimi API kabulü

`node scripts/acceptance/s10-hosted-work-calendar.mjs` mevcut development projesindeki açık seçilmiş Pro test merkezinde çalışır. README'deki `FTK_ACCEPTANCE_*` girdileriyle mevcut aktif test disiplini ve gelecekte açık test aralığı verilir; runner disiplin/rol/ürün kurmaz. Başlangıçtaki takvim kuralları ve kapanışlar korunarak yalnız test seansına dar bir kapanış önerilir. Etki birden fazla veya başka seans içeriyorsa ayar yazılmadan durulur. Canlı seans nedeniyle `OPEN_OPERATIONS_EXIST`, açık iptal sonrası ayar/replay ve yeni kaynak gerektirmeyen Pro seansında `RESOURCE_CONFLICT` doğrulanır.

Yanıt kaybında create/cancel aynı operation_key ile uzlaştırılır; başarısız olması beklenen create beklenmedik şekilde commit etmişse o seans da test-owned temizliğe alınır. Ayar restore'u önceki effective değeri ve local/default kaynağını birlikte korur; başka writer değişmişse ezmez. İptal/ayar geçmişi silinmez; finans, katılımcı veya görev yaratılmaz. Native oturum local logout ile kapatılır. Gerçek yerel/hosted sonuç ve kalan S10 sınırı [kabul kaydında](00-FtkSaaS-yeni-sohbet-devir.md#s10-is-takvimi-hosted-kabulu) tutulur.

Bütün parola PUT denemeleri beklenmedik başarı ve belirsiz HTTP sonucunda da aday parolayı saklar; özgün parola geri yüklenip bağımsız login ile doğrulanır. Bunlar CLI ortam secret'ı veya proof üretmez; girdiler yalnız ignored `.dev`/özel süreç belleğinde tutulur. Sonuçlar sır/parola/JWT/posta gövdesini içermez; testin açtığı oturumlar kapatılır. Gerçek kaynak/hosted sonuçlarının tek sahibi [güncel kabul](00-FtkSaaS-yeni-sohbet-devir.md#s10-crm-ve-s08-native-kabul-paketi) dosyasıdır.

## Native parola güvenliği (XREQ-002)

Native Auth'ın mevcut parola kontrolü ve güvenlik e-postası [tek tüketici sözleşmesine](../../../docs/settings.md#parola-değişimi-ve-güvenlik-bildirimi) göre yapılandırılır. Kaynak [auth-password-security.mjs](../scripts/auth-password-security.mjs), ileti [native şablondur](../supabase/templates/password_changed_notification.html). Yalnız mevcut development projesi desteklenir. Kabul edilmiş kaynakta, backend dizininden:

```sh
node scripts/auth-password-security.mjs --plan
node scripts/auth-password-security.mjs --check gwyprhenabtpkbojephw
node scripts/auth-password-security.mjs --apply gwyprhenabtpkbojephw
```

Check/apply `SUPABASE_ACCESS_TOKEN` ortam değişkenini kullanır; secret komut satırına/yazıya konmaz. Plan ağ çağrısı yapmaz, check yalnız okur. Apply yalnız mevcut-parola/nonce, password_changed etkinlik/konu/şablon ve native e-posta OTP süresi alanlarını Management API ile yazar; sonra bağımsız GET ile birebir doğrular. SMTP/anahtar/Google/JWT/redirect izin listesi değiştirilmez; tam config veya credential çıktı verilmez. Auth SiteURL HTTPS kök origin olmalıdır; gerçek `/forgot-password` ve mevcut `/auth/callback?next=/reset-password` redirect izinleri önceden doğrulanır. Bu ayrı işletim adımıdır; SQL/Edge CD veya config.toml hosted ayarları otomatik uygulamaz.

Önceki CLI 2.122.0 native kabulünde TOML mevcut-parola zorunluluğunu sunmuyordu ve custom content_path desteği sınırlıydı; CLI 3.0.0 yükseltmesi bu hosted kabulünü kendiliğinden kapatmaz. Yerel TOML yalnız native reauthentication ve bildirim etkinliği/konusunu taşır; hosted HTML ve iki güvenlik ayarı development config aracıyla yönetilir. Test için ikinci bir Auth süreci çalıştırılmaz. Uygulamanın native oturum/MFA/kimlik entegrasyonu CI'da; mevcut-parola/nonce ve gerçek dış posta kabulü hedef hosted sağlayıcıda doğrulanır.

Hosted kabul: eksik/yanlış mevcut parola reddi; 24 saatten yeni/eski oturum, refresh sonrası eski oturumun nonce zorunluluğu, yanlış/süresi dolmuş/tüketilmiş nonce ve doğru mevcut parola + nonce ile değişim; yalnız kayıtlı ana adrese bildirim; gerçek bağlantıdan recovery/PKCE ve yeni parola; eski/yanlış/süresi dolmuş/tekrarlanmış proof reddi; diğer session refresh ve Edge erişiminin reddi, current recovery session'ın korunması. Parola tekrar eşleşmesi frontend kabulündedir. Native bildirim gönderimi best effort'tür: SMTP başarısızlığı parolayı geri almaz; Auth/provider logları kişisel veri/sırlar dışarı çıkarılmadan kontrol edilir. Production dağıtımı bu komutun kapsamı değildir.

Başarılı aynı kaynak receipt’i ve canlı Edge hash/version/ACTIVE/JWT eşleşmesi tekrar deploy’u önleyebilir.

Migration içeriği manifest ve uzak migration geçmişiyle karşılaştırılır; bilinmeyen, sapmış veya yinelenmiş sürümde durulur. Otomatik history repair, reset veya seed yoktur. Uygulanan migration geri yazılmaz. Kabul edilen kaynak ilerletilir; önceki kod sürümüne dönmek DB’yi geri almaz. `backend-v1` dependency-complete bundle ve `verify_jwt=true` ile yayımlanır. Smoke, dış e-posta göndermeyen sentetik native kullanıcıyla Auth→Edge→RPC, tenant/RPC/JWT/session, RLS/ACL ve fixture cleanup doğrular. Kullanıcının UUID’sine bağlı dar temizlik hata halinde de uygulanır. Smoke tüm workflow/sağlayıcı/restore kabulü değildir. CD metadata/DB-tip artifact’ının kapsam ve sınırı [dokümantasyon rehberindedir](documentation-development.md).

## S14 bağımsız backend kabulü

S14'ün HTTP kabulü için frontend uygulaması veya ekranı gerekmez. Backend'in mevcut `signPublicApplication` helper'ı ile doğrudan `POST /functions/v1/backend-v1/public_application_submit_v1` çağrılır. `public-application-gateway.mjs` mevcut sunucu adaptörüdür; yalnız Vercel'de platformun doğruladığı bağlantı IP'siyle kullanılır. Ayrı bir frontend formu, yeni public motor veya CAPTCHA bypass yolu kurulmaz.

1. Ayrılmış development org/merkez ve yetkili native kullanıcıyla normal API'den gelecek ders oluştur, `publication_set_v1` ile açıkça yayınla; public takvimde bu yayını oku. Ücret/koşul/politika fixture girdileri önceden açık seçilmiş olmalı; canlı kayıttan tahmin edilmez.
2. Güvenilir kabul hostunda mevcut ingress secret, native gateway için legacy anon JWT, proof'u alan kabul ziyaretçisinin güvenilir bağlantı IP'si ve yayımlanan derse ait request hazırla. Backend sunucusunun keyfî IP'si veya ziyaretçinin beyan ettiği forwarded header kullanılmaz. `signPublicApplication` exact ham body/path/time/IP'yi imzalar. Bu işletim yetkisi anonim istemciye veya browser bundle'a verilmez. `FTK_PUBLIC_HASH_SECRET`, `FTK_TURNSTILE_SECRET` ve etkin uygulama hostname'i Edge tarafında bulunmalıdır.
3. Kullanıcının seçimiyle Public/Turnstile kabulü normal Chrome'da yürütülür; diğer kontroller headless olabilir. Geçerli proof mevcut onaylı sağlayıcı/site key ve izinli hostname'de `public_application` action'ıyla elde edilir. Bunun uygulamanın üretim ekranından gelmesi gerekmez; backend'e ait ayrı kabul istemcisi kullanılabilir. Bilinmeyen site key/secret/domain uydurulmaz; dummy key, sentetik verified context veya doğrudan RPC bu hosted kanıt yerine geçmez. Sağlayıcı hesabına erişim/config eksikse backend işletim girdisi olarak kaydet; frontend uygulamasının tamamlanmasını bekleme.
4. İmzalı gerçek HTTP submit ardından yetkili native oturumla inbox'u yeniden oku; kayıt yalnız doğru merkeze düşmeli. Yetkisiz inceleme reddini ve yetkili `public_application_review_v1` sonucunu doğrula. Aynı niyetin retry'ı tek başvuru bırakmalı; yanlış imza, body/path/time/IP, token/action/hostname, rate ve yayın kapatma sınırları kendi uygun kaynak/native/hosted kanıtıyla ayrı yazılır. Başvuru tek başına hesap, satış, rezervasyon veya pazarlama izni oluşturmaz.
5. Yalnız owned yayını kapat, owned dersi sürümlü preview/apply ile iptal et; başka başvuru/rezervasyon etkisi varsa dur. Açılan native oturumu local logout ile kapat, eski token reddini doğrula; mevcut S08 eski oturumuna dokunma. Kanıt türünü kaynak/native/hosted diye açık etiketle; yalnız gateway400 veya güvenli ret bütün kabul değildir.

Frontend'in site key render etmesi, widget reset/retry, `/p/[slug]` ekranı, erişilebilirlik ve canonical deployment'ı kendi tüketici kabulüdür. Kullanıcının ayrıca yetkilendirdiği canlı gateway kurulumu yapılabilir; bu yardım S14 için yeni bir frontend bağımlılığı yaratmaz. Güncel ilerleme burada çoğaltılmaz; [S14 kabul kaydı](00-FtkSaaS-yeni-sohbet-devir.md#s14-backend-kabul-siniri) kullanılır.

`node scripts/acceptance/s14-hosted-public.mjs` bu doğrudan alım/inbox/inceleme dilimini çalıştırır. Yalnız mevcut development projesine bağlanır. Önceden ayrılmış ve yayınlanmış ders için `FTK_ACCEPTANCE_ORG`, `FTK_ACCEPTANCE_CENTER`, `FTK_ACCEPTANCE_SESSION`, `FTK_ACCEPTANCE_PUBLICATION`; yetkili native hesap için `FTK_ACCEPTANCE_EMAIL`, `FTK_ACCEPTANCE_PASSWORD`; mevcut enabled legacy anon JWT için `FTK_ACCEPTANCE_APIKEY`; güvenilir host/proof için `FTK_ACCEPTANCE_INGRESS_SECRET`, `FTK_ACCEPTANCE_VISITOR_IP`, `FTK_ACCEPTANCE_BOT_PROOF` gerekir. Değerler process ortamında verilir; komut argümanına veya kaynaklara yazılmaz.

`FTK_ACCEPTANCE_STATE`0700 private dizindeki0600 journal yoludur. Tek writer kilidi ve fsync/atomic rename kullanılır; eski `.lock`/`.pending` otomatik silinmez, belirsiz durumda aynı niyetin receipt'i ve canlı kayıt uzlaştırılır. State/proof/credential sohbete veya artifact'e konmaz. Runner yayın/merkez/actor eşliğini kontrol eder, kendi UUID'sinden türetilen `example.invalid` başvurusunu oluşturur, aynı niyeti tekrarlar, tek kayıt ve versioned `close` incelemesini doğrular; kişi/satış üretmez. Response-loss review aynı key/body ile kurtarılır. Yeni native session kimliği ve oluşturulma zamanı domain işleminden önce private journal'a alınır. Önceki koşudan kapanmamış yalnız kayıtlı test oturumları aynı actor ve created_at ile doğrulanıp selected revoke/absence readback ile çözülür; others modu kullanılmaz. Yeni native session local logout ve eski JWT reddiyle kapanır; hiçbir kayıtlı cleanup borcu varken başarı dönmez. Runner yayını/dersi oluşturmaz veya kaldırmaz: `fixtureRetirementRequired:true` döner; yalnız bu alt zincirin başarısıdır. Owned yayının kapatılması ve dersin güvenli iptali ayrıca tamamlanmadan S14 bütünü kapanmaz. Unit transport doubles gerçek sağlayıcı kabulü değildir.

## Worker işletimi

Kabul edilmiş migration/rol kaynakları kurulduktan sonra [ops-cron-install.sql](../scripts/ops-cron-install.sql) yönetici oturumunda atomik çalıştırılır. Aynı ad/rol yeniden kurulumda job güncellenir; mükerrer görev yaratılmaz. Geçici provisioning üyelikleri ve Cron erişimi işlem sonunda kaldırılır. Beş dedicated LOGIN yalnız kendi worker grubunu devralır; superuser/createdb/createrole/replication/bypassrls verilmez. Gerçek `session_user` kapısı SET ROLE ile aşılmaz.

Tenant binding ilgili p01/p05/p06/p07 scope tablosunda açık organizasyon ve lane LOGIN rolüne bağlanır; privacy global null kapsamı ayrıca açık seçilir. Tenant/config uydurulmaz. Lane sözleşmesi [WF20](../../../docs/workflows.md#wf20); sağlık sorgusu [ops-cron-health.sql](../scripts/ops-cron-health.sql). Job owner/schedule/active ve gerçek heartbeat birlikte okunur; idle/claim0 gerçek iş yükü başarısı değildir.

Bir lane için `private.ops_worker_health.enabled=false` yeni claim’i durdurur; sürmekteki işi iptal etmez. Yeniden başlatma true ile yapılır. Tam scheduler durdurma ilgili job için `cron.alter_job(..., active:=false)`; kaldırma yalnız ilgili job için `cron.unschedule` ile yapılır. Cron extension’ını drop etmek rollback yöntemi değildir. `CALL private.ops_run(...)` tek başına autocommit çalışır; claim COMMIT yolu transaction bloğuna sarılmaz. Binding/rol kaybı kapalı kalır; yeniden binding önce yetki ve canlı kaynak doğrulanır.

Kesinti denetimi lease expiry/reclaim, aynı işte tek domain sonuç, hata rollback, disable/rebind/restart ve expired export byte temizliğini ayrı sınar. Üç işlik bounded kabul yük SLA değildir. Privacy partial/retry_wait manifesti DB/Auth/Storage/export/backup fiziksel imha kanıtı değildir.

## Asgari yedek ve izole geri yükleme

Bu teslimin O11 kontrolü, [ürün teslim sınırındaki](../../../docs/contracts/01-FtkSaaS-urun-kapsam-sozlesmesi.md#bu-teslimin-veri-güvenliği-sınırı) tek yedek→ayrı hedef→uygulama açılışı/temel okuma işlemidir. Sağlayıcının kendi kurduğu `auth.schema_migrations` metadata’sı veri yedeğine dahil edilmez. Kaynak hesap/organizasyon/merkez hedefin yeni native Auth oturumu ve mevcut Edge/RPC okumalarıyla karşılaştırılır; yalnız DB sorgusu/health yeterli değildir. Sonunda test oturumu kapatılır, kaynak yeniden okunur ve geçici hedef kaldırılır. Kabul/hash/sonuç [tek durum sahibindedir](00-FtkSaaS-yeni-sohbet-devir.md#o11-asgari-restore-kabulu).

Bu asgari işlem aşağıdaki Business sonrası tam restore/sicil/non-resurrection hedeflerini yeni teslim önkoşulu yapmaz; mevcut kaynak ve testleri korur.

## Managed restore prosedürünün sınırı

Kaynak ve hedef ayrı ve açık tanımlanır; deneme hedefi izole olmalıdır. Managed Auth/Storage şema sahiplerini platform kurar. Uygulama şema/rol/owner/ACL/RLS/policy/fonksiyon güvenlik ayarları korunur; `--no-owner/--no-acl` ile güvenlik farkı gizlenmez. Aynı read-only snapshot’tan veri ve uygulama migration geçmişi alınır; sağlayıcının kendi migration tabloları hedef platforma bırakılır. Rol üyelikleri mevcut grant zinciriyle karşılaştırılır, gereksiz grant tekrarları yapılmaz. Worker parolası veya provider secret’ı SQL dump’tan geri gelmiş sayılmaz.

Restore doğrulaması tablo içerik checksum’ları, etkin ACL (NULL için acldefault), RLS/policy ve fonksiyon owner/security-definer/config/EXECUTE karşılaştırmasını kapsar. Native kullanıcı gerçek girişle ve aynı UUID ile denenir; eski access token’ın farklı projede geçerliliği varsayılmaz. Edge aynı kabul edilmiş kaynaktan kurulur. Storage metadata ve bütün nesne baytları ayrı taşınıp checksum/erişimle doğrulanır. Scheduler/binding, gerçek iş yükü ve kesinti toparlanması ayrıca sınanır. Tek dosya veya idle worker deneyi bütün envanter kabulü değildir.

`auth.mfa_factors` history ve kimlik projeksiyon trigger’ları, private identity/contact tabloları owner/ACL ve purge envanterine dahildir. Google-link/TOTP intent ve fence katmanları kaldırılmıştır. Faktör secret/OTP/token loga veya uygulama audit’ine taşınmaz. Kaldırılmış özel account_password_transactions/reset trigger taslağı restore listesine eklenmez. RPO/RTO; hazırlık, veri, Auth, Edge, Storage, config ve worker geri dönüşünü kapsayan gerçek ölçüm ister.

### P07 site sunucusu adaptörü

`transports/crm-web-form-gateway.mjs` içindeki `createCrmWebFormHandler(kind, config, env)` yalnız sunucu içindir. Site bunları yeni gönderimde bir kez üretir; belirsiz retry boyunca key/zaman/payload aynı kalır. Yeni gerçek başvuru yeni key alır. request_id izleme içindir. submitted_at tüketicinin beyan ettiği gönderim zamanıdır; kanıtlanmış onay tıklama zamanı değildir. ### Meta kalıcı ACK ve tekil worker

Büyük batch için hosted aday yolu `createMetaQueuedWebhookHandler(config,{client})` ve `createMetaQueueWorker({...config,lease_seconds,retry_seconds},{client,fetchImpl})` çiftidir. Senkron adapter geriye dönük kaynak/test için korunur; büyük Meta batch’inde host adayı olarak kullanılmaz.

Queued receiver ham imza/route doğrulaması sonrası `private.crm_meta_enqueue` ile bütün batch’i tek transaction’da kaydeder. Yalnız provider kimlikleri, provider bildirim/oluşum zamanı, bilinen reklam kimlikleri ve güvenilir form/org/merkez snapshot’ı tutulur; token, alan cevabı veya intake kuyruğa girmez. `notification_sent_at` farklı retry yeni başvuru değildir; değişmiş bilinen lead metadata’sı veya formun tenant/merkez değişimi fail-closed olur. ## Restore ve yeniden canlanma engeli

`apps/backend/scripts/restore-guard.mjs` restore öncesinde silinmiş subject referanslarını denetler. Restore/purge yapmaz, erişim açmaz. Başarılı çıktı yalnız JSON referans taramasıdır; Storage, config, WAL/MVCC ve backup expiry ayrıca doğrulanır. Genel privacy orkestrasyonu ve hosted uçtan uca kabul açık kalır.

```sh
node apps/backend/scripts/restore-guard.mjs --snapshot /private/snapshot.json --ledger /independent/current-erasure-ledger.json --trust /independent/current-restore-trust.json
```

Trust dosyası yedekten alınmaz. Restore anındaki bağımsız sicilden güncel açık anahtar, ledger SHA256/sequence ve kaynak ref alınır; seçilen snapshot SHA256 ile bağlanır. Araç eski ama kendi içinde tutarlı trust/ledger çiftinin gerçekten güncel olduğunu dış servise bağlanmadan bilemez. Güncel bağımsız head'i elde etmek pipeline/operatör sorumluluğudur; eski trust ve ledger'ı birlikte geri yüklemek yasaktır. Özel anahtar istenmez.

Trust alanları: format=1, source_project_ref, snapshot_sha256, ledger_sha256, ledger_sequence, ledger_public_key_pem. Ledger alanları: format=1, source_project_ref, sequence, issued_at, erasures, signature. Girdiler request_id, kind(account/organization), subject_ids, completed_at içerir. Signature dışındaki payload anahtarları sıralanmış canonical JSON olarak Ed25519 ile imzalanır; timestamp UTC ISO milisaniye biçimindedir. Silme orkestrasyonu tüm silinmiş kök/bağlı subject kimliklerini sicile yazmalıdır; eksik sicil kapsamını bu araç keşfedemez.

Snapshot project_ref ve tables dizisi içerir; tablolar schema/table/rows biçimindedir. UUID referansları kök/foreign key/JSON değer ve anahtarlarında/metin içinde aranır. Eşleşmede bütün aday reddedilir; hukuki arşiv dahil hiçbir satır sessizce filtrelenmez. Digest/imza/sequence/proje/şema hatası başarısız çıkış üretir. Çıktı yalnız güvenli sayım/hash/kapsamdır; satır veya kimlik basılmaz. Bu kapı geçse bile diğer restore/non-resurrection kontrolleri tamamlanmadan hizmet erişimi açılmaz.


### Sicil adaptörü ve zorunlu doğrulama sınırı

`erasure-register.mjs` bağımsız dosya siciline imzalı kayıt ekler: caller beklenen önceki hash/sequence'i sağlamalıdır. Aynı kayıt tekrarı byte-identical replay'dir; aynı request_id/farklı içerik reddedilir. Tek writer lock, exclusive pending dosyası, fsync ve atomik rename kullanılır. Çökmeden kalan lock/pending otomatik silinmez: operatör önce yaşayan writer olmadığını, imzalı son head'i ve bağımsız checkpoint'i doğrular. Rename sonrası fsync hatasında commit sonucu belirsizdir; kör retry yerine head okunup CAS ile karşılaştırılır.

Bu modül hukuki onay veya purge kanıtı üretmez. İmzalama anahtarı yalnız doğrulanmış silme sonucunu kaydeden orkestratöre verilmelidir. Sicil dizini/anahtar ve rollback'i engelleyen güncel head checkpoint'i restore kapsamının dışında, ayrı yetki ve yedeklemeyle işletilmelidir. Yerel test dosyaları üretim sicili kurulumu değildir. Saklama/expiry, anahtar yönetimi ve bağımsız kalıcı depolama kabulü henüz açıktır.

`guarded-restore.mjs` aynı sicil kilidi altında guard'ı çalıştırır; callback adaptörüne doğrulanmış ve recursive frozen snapshot verir. Eski `apply` API'si callback tamamlanmasıdır; callback kendi commit'ini yaptıysa son guard bunu geri alamaz. Transaction kullanan yeni caller `transaction.prepare/commit/rollback` sağlar; prepare kısmen hata verse de rollback çağrılır, son sicil hash/pending ve bağımsız checkpoint kontrolü bitmeden commit çağrılmaz. Transaction prepare'ın üçüncü argümanı hash ile bağlanmış snapshot byte kopyasıdır; kayıpsız sayı işleme için kullanılır. `readCheckpoint` verilmişse başta ve prepare sonrasında tam trust nesnesiyle birebir eşliği gerekir; fonksiyon güncel bağımsız kaynağı gerçekten okumalıdır. Sabit eski trust döndüren callback güncellik kanıtı değildir. Commit denemesi hata verirse `RESTORE_COMMIT_OUTCOME_UNKNOWN`; otomatik retry yoktur. Rollback hatası da başarı değildir. Callback/transaction sonuçları hizmet açma izni değildir.

### İzole PostgreSQL satır yüklemesi

`postgres-restore.mjs` içindeki `restorePostgresSnapshot` yukarıdaki transaction protokolüne bağlanan somut, veri-satırı yükleyicisidir. `connectionString`, `target`, snapshot/register/trust ve zorunlu `readCheckpoint` alır. ConnectionString yalnız query/hash içermeyen PostgreSQL loopback URL'sidir; target.database `ftk_restore_*`, target.system_identifier beklenen PostgreSQL instance kimliği, target.server_address ayrı güvenilir ön kontrolde `host(inet_server_addr())` ile okunan exact IP veya Unix socket için açık `null` onayı, target.tables exact `{schema,table}` listesidir. Bu hedef onaylı ayrı bir deneme DB'si olmalıdır; loopback bir production tüneline yönlendirilmez. URL/kimlik/adres/tablo listesi yedekten yetki olarak alınmaz. Sunucunun port yönlendirmesi arkasındaki private IP’si ile istemcinin loopback adresi aynı olmak zorunda değildir; CIDR/host adı/wildcard kabul edilmez, sunucu adresi exact bağlanır. Supabase CLI3 native proxy istemciye loopback TCP sunarken backend Unix socket kullanabilir: o durumda SQL adresi `NULL` gelir ve yalnız açık `server_address:null` kabul edilir. Eksik/undefined adres kabul edilmez; `null` TCP IP yerine geçen bir wildcard değildir. Data ve maintenance aynı onaylanmış adres/Unix türü ile instance kimliğine uymalıdır.

Hedef şema/roller/güvenlik önceden güvenilir kaynaktan kurulmalıdır. Yükleyici tablo yaratmaz, truncate/merge/DDL dump çalıştırmaz, policy/trigger/constraint kapatmaz. Instance/adres/database doğrulaması ardından `ALLOW_CONNECTIONS false` veri transaction'ı dışında uygulanır. Diğer hedef oturumu varsa yükleme durur. PostgreSQL hedef DB içinden kendi bağlantılarını kapatmayı yasaklar. Ayrı aynı-instance `postgres` maintenance bağlantısı default read-only autocommit metadata okur; yalnız exact recovery DB için kapatma işlemini explicit READ WRITE transaction içinde uygular. Instance/adres eşliği bu yazıdan önce de doğrulanır; veri socket’i/ROLLBACK’i hata verse bile finally kolunda aynı bakım bağlantısı kapıyı tekrar kapatmayı dener; kapatma veya rollback hatası başarılı sonuç üretmez; böylece SERIALIZABLE içindeki eski pg_database görünümü son kapı kontrolünü yanıltmaz. İki DB'de pg_control_system okumaya ve yalnız recovery DB'de bağlantı kapısını kapatmaya yetki gerekir. Yükleyici kapıyı açmaz; rollback bunu geri alamaz. COMMIT'ten hemen önce güncel kapı tekrar okunur; ayrı yetkili operatörün son kontrol sonrasında kapıyı zorla açması bu aracın transaction garantisiyle engellenemez. Kurtarma boyunca ayrı bakım yetkisi ve ağ izolasyonu korunmalıdır.

ACCESS EXCLUSIVE tablo kilitleri, boş hedef, birebir sütun kümesi ve normal origin replikasyon modu gerekir. `row_security=off` RLS'yi aşma yetkisi vermez: politika filtrelemesi gerekecek rolde hata üreterek gizli mevcut satırların boş sanılmasını engeller. User trigger, rule, inheritance/partition, generated/identity sütun taşıyan tablolar desteklenmez; sessizce atlanmaz. Veri türü/domain/fonksiyonları dahil ön kurulu DDL güvenilir olmalıdır; bu araç keyfî DDL sandbox'ı değildir. Snapshot sırası korunur; deferrable constraint'ler commit öncesi yeniden immediate yapılır. Her tablo typed JSONB satırlarıyla EXCEPT ALL iki yönlü karşılaştırılır. bigint/numeric/nested JSON sayıları özgün JSON token'larından yüklenir; JavaScript Number'a yuvarlanmış kopya geri yazılmaz. PostgreSQL hata mesajı/detail/query/cause dışarı taşınmaz; statik hata kodu ve varsa SQLSTATE döner.

Başarılı `isolated_postgres_rows_restored` yalnız exact seçili veri satırlarının kapalı hedefte commit edildiğini belirtir. Sequence sayaçları, şema/migration/owner/ACL/RLS karşılaştırması, native Auth giriş/UUID, Storage baytları, Edge/config/secret, worker binding ve RPO/RTO ayrı tam kurtarma kontrolleridir. Bu desteklenmeyen yüzeyleri boş/başarılı sayıp hizmet açılmaz; O07/O08/O09 bütünü için gerçek izole tam snapshot ve bağımsız güncel sicil kabulü gereklidir. Mevcut `database.test.mjs` kökündeki `postgres-restore-acceptance.mjs` yalnız kendi oluşturduğu ayrı recovery DB'lerinde bu mekanik sınırları sınar.

Tenant gönderici/app origin/provider secret referansı ilk claim’de iş üzerinde sabitlenir; config değişimi belirsiz önceki işin sağlayıcı hesabını veya mesajını değiştirmez. Service-role anahtarı değişirse daha önce o anahtarla mühürlenmiş gönderilmemiş davetler çözülemeyebilir ve güvenli yeniden davet değerlendirmesi gerekir.

`invitation-cron-install.sql` native pg_cron/pg_net’i ve yalnız `private.invitation_dispatch()` çağırabilen `ftk_ops_invitation` LOGIN rolüne ait 30 saniyelik tek görevi kurar. Private `invitation_delivery_tick` sınırı kısa ömürlü HMAC ister; her tick UUID’si DB’de bir kez tüketilir. Kuyrukta iş/tenant/alıcının verisi veya kalıcı yetkili anahtar yoktur. Edge iç handoff’u mevcut `outbox_deliver_v1` service-only RPC üzerinden yürür; frontend veya anon bu RPC’yi çalıştıramaz. İnsanın native Auth akışı değiştirilmez. HTTP çağrı bütçesi 60 saniye, iş lease’i iki dakika, toplam deneme üçtür. Timeout/5xx/429/eşzamanlı idempotency isteği 30/60 saniye backoff ile aynı job anahtarıyla tekrar edilir; kalıcı 4xx kapanır. Resend 24 saat sakladığı için ilk denemeden 23 saat sonra belirsiz işe yeniden gönderim yapılmaz. Config secret’ı eksik iş safe hata ile kapanır ve diğer işler devam eder.

Durdurma: `private.invitation_dispatch_config.enabled=false` veya ilgili `private.invitation_sender_config.enabled=false` yeni gönderimi durdurur. Tam Cron durdurma yalnız `ftksaas-invitations` job’ında `cron.alter_job(...,active:=false)` ile yapılır; extension drop edilmez. Gönderim öncesi kontrol ile dış HTTP yan etkisi atomik değildir. Kontrolden sonra başlayan revoke, sağlayıcıya verilmiş postayı geri alamaz; davet token’ını geçersiz kılar. Gönderim kabulü gerçekleştiyse bu kanıt korunur. Gerçek dış teslim ve doğru/yanlış hesap, expired/revoked token, link çakışması kabulü yetkilendirilmiş gerçek test alıcısıyla ayrıca yapılır; sentetik sağlayıcı testi bunu kapatmaz.

### Resend teslim webhook’u

Kabul edilmiş email-events kaynağı dağıtıldıktan sonra mevcut Resend hesabında webhook URL’si `https://<project>.supabase.co/functions/v1/resend-webhook` olarak seçilir. `email.sent`, `email.delivered`, `email.delivery_delayed`, `email.bounced`, `email.complained`, `email.failed`, `email.suppressed` olayları kullanılır. Endpoint signing secret güvenli ortamdan `FTK_RESEND_WEBHOOK_SECRET` Edge secret’ına konur; Auth/service-role/SMTP anahtarı yerine geçmez. Eksik secret’ta giriş kapalıdır. Sağlayıcı raw body + svix-id/timestamp/signature gönderir. Ayrı fonksiyon native HTTP handler ile çalışır ve CORS başlığı üretmez; hosted config yalnız bu fonksiyonda `verify_jwt=false` olur. Kullanıcı JWT'si istemez; provider imzası zorunludur. `backend-v1` JWT kontrolü açık kalır. `standardwebhooks` öncesi üç Svix başlığı `webhook-id/timestamp/signature` olarak eşlenir; secret `whsec_` biçiminde değiştirilmeden verilir. İmza reddi403, eksik config/geçici kalıcılaştırma hatası503'tür. Deploy ayrı kaynak hash/sürüm makbuzunu ve JWT olmadan403 imza reddini doğrular; bu smoke gerçek sağlayıcı/alıcı kabulünün yerine geçmez. Kurulum dış posta göndermez; gerçek yetkili olay ve teslim kanıtı ayrıca doğrulanır. Sağlayıcı olayları yalnız provider reference üzerinden mevcut davet veya işlemsel email job’una bağlanır; dashboard’dan webhook tekrar oynatımı aynı kalıcı kimlikle tekildir. Güncel sağlayıcı protokolü: [Resend doğrulama](https://resend.com/docs/webhooks/verify-webhooks-requests), [Standard Webhooks](https://github.com/standard-webhooks/standard-webhooks), [Supabase dış webhook güvenliği](https://supabase.com/docs/guides/functions/auth#external-webhooks).

### P14 işlemsel email etkinleştirme

Kaynak aday/main/development kabulünden sonra mevcut gönderici kurulumunda `--transactional-email` açık seçilir. Bu anahtar yalnız belirtilen org için transactional_enabled açar; Pro/Business/F26 ve bireysel email/transactional tercihi yine zorunludur. Başlangıçta kapalı tercih topluca açılmaz, eski bildirimler aktarılmaz. Cron ve Vault gönderici kimliği davet lane'iyle paylaşılır; Native Auth değişmez. `FTK_RESEND_WEBHOOK_SECRET` güvenli ortamdan verilirse kurulum Edge secret'ını da eşitler. Yeni webhook, secret eşitlenip imza girişinin çalıştığı doğrulanmadan açılmaz. Eski proje webhook'u repoint/rotasyon yapılmaz. Genel email işi mevcut inbox okumasındaki email_job ile izlenir; başka alıcı/tenant'a görünmez.

## Geçici DB export baytlarının imhası

Mevcut P06 claim, yedi günlük dosya süresi dolunca en çok100 DB export bayt nesnesini temizler. İşletim rolünün canlı org bağlantısı gerekir; yeni scheduler veya genel purge endpoint'i yoktur. Hold altında kalan baytın indirme erişimi açılmaz. Hesap hold'u, hold kaydının organizasyonu farklı olsa da hedef hesabın export'larında geçerlidir; diğer dosya/rapor/job/org hold'ları kendi kaynağında denetlenir. `review_at` otomatik kaldırma zamanı değildir.

Hesap silme için mevcut global privacy worker'a ek `private.account_export_erasure_scopes` içinde gerçek LOGIN rolü ile tek onaylı hesap bağlantısı gerekir. Migration bu tabloya hedef eklemez. Yalnız `account_delete`/`deletion_pending`, owner blokajı olmayan ve aktif hesap bağları kapatılmış hedef kabul edilir. Operator bağlantı kaldırması aynı purge transaction'ı ile seri hale gelir; SET ROLE başka hesabın izni değildir. `privacy_execute_v1` içindeki bu alt aşama report requester/private job/file/account/person/center/org ve gerçek checksum/boyut zincirini denetler. Eksik veya paylaşılan dosya işaretinde otomatik düzeltme yapılmaz, işlem geri alınır.

`private.p06_export_purges` yalnız dosya/rapor ve doğrulanmış sabit hesap kimliği, sebep/politika sürümü, byte sayısı/hash ve zamanı tutar. İçerik kopyası yoktur. Hesap referansı kasıtlı olarak live-account FK değildir: expiry org kilidi ile privacy hesap kilidinin ters sırada beklemesi önlenir; doğrulama helper'ı ve kapalı tablo yetkisi korunur. `private.account_export_erasures` talep alt aşamasının tekil kanıtıdır. Her ikisi geç hata/lease süresi aşımında bayt silme ile birlikte rollback eder. Kaynak import CSV, belge/onay, tenant kişi/finans ve rapor metadata'sı bu yoldan silinmez.

İç manifestte `exports.database_exports=completed` genel exports/Storage/backup veya hesabın tamamlandığı anlamına gelmez; ana talep partial/pending kalır. Bu DB kanıtı bağımsız imha sicili veya yedek yokluk kanıtının yerine geçmez. İptal/restore ve operator incelemesinde bu sınır korunur.

## Native Auth principal imhası işletimi

`native-account-erasure.mjs` yalnız dedicated privacy worker bağlantısında mevcut claim request'iyle çalışır; native Auth admin anahtarı DB worker rolüne yetki eklemez. `private.account_auth_erasure_scopes` exact db_role/account_id/provider_origin ve PostgreSQL system_identifier bağını tutar; migration hiçbir hedef bağlamaz. Scope kurulumu yalnız onaylı imha hedefi için yetkili işletim adımıdır. Hosted origin mevcut projenin HTTPS köküdür; izole kabulde yalnız loopback portu kullanılır. Restore/clone sırasında binding/permit ve admin anahtarları taşınıp etkinleştirilmez; fiziksel klon system_identifier'ı koruyabileceğinden instance bağı tam restore erişim kapısının yerine geçmez.

Runner girdileri dedicated DB bağlantısı, claim request, API URL ve native admin key'dir; çıktı yalnız güvenli state'tir. Native HTTP sonucu belirsizse immutable proof ve sağlayıcı readback uzlaştırılır; eski izinle kör tekrar yapılmaz. Provider transaction'ındaki fence yeni hold'u ve kilit beklerken dolan lease'i reddeder. Principal yokluk kanıtı transaction sonundaki ertelenmiş constraint trigger'ında, nested Auth FK cascade'leri bittikten sonra yazılır. Commit'teki proof hatası provider silmesini ve tüm çocuk kayıtlarını birlikte geri alır. Native Storage sahipliği varsa işlem durur; Storage metadata'sı SQL ile silinmez ve ticari nesneler başka kullanıcıya keyfî devredilmez. Principal silme kanıtı Auth audit verilerinin imhası veya bütün privacy talebinin kapanışı değildir.

### Auth kalıntı aşamasının kapsamı

Aynı exact Auth target binding'i yeni kalıntı aşamasını da kapsar; migration yeni hedef bağlamaz. Private helper'a service/worker/in-app execute hakkı verilmez. Native DELETE'in ertelenmiş proof trigger'ı ve mevcut leased privacy executor sınırından çalışır. Global/hesap ve somut flow/audit hold'u blokajdır; review_at expiry değildir. İki farklı Auth kimliği içeren flow veya target refresh token'ın başka kullanıcı session'ına bağlanması integrity hatasıdır; otomatik veri düzeltmesi/silme yapılmaz.

| Yüzey | Uygulanan yöntem / koruma |
|---|---|
| Hedefe ait geçici flow_state ve eski oturumsuz refresh token | Canlı satır silme; kalan hedef satır kontrolü, late failure rollback |
| Native audit hedef actor | Yalnız actor_username/actor_name ve actor IP kaldırılır; sabit actor UUID/action/zaman korunur |
| Native audit hedef subject | Yalnız traits.user_email/user_phone kaldırılır; foreign actor, identity/factor ve diğer kanıt aynen korunur |
| Başka hesap/tenant kanıtı | Değiştirilmez; karma flow sahipliği otomatik geniş silme gerekçesi değildir |
| Sağlayıcı dış logları / diğer Auth / backup | Bu helper'ın tamamlanma kapsamı değildir; ana Auth yüzeyi pending kalır |

İlk kalıntı receipt'i request/subject/policy_version ve ilk pass satır sayılarıyla append-only'dir. Sonraki yeni claim'lerde aynı helper tekrar tarar; her pass sonucu checked_at ve o pass sayımlarını manifestte taşır. Böylece ilk transaction'dan sonra commit eden provider audit kopyası sonraki yetkili geçişte yeniden ele alınır. Aynı worker receipt replay'i tekrar iş yapmaz. Bu düzen bütün provider log retention'ını veya nihai yok etmeyi kanıtlamaz; kaynaklı yöntem tanımı teknik sözleşmenin19. bölümündedir.

## O02 alarm müdahalesi

Bu teslimin asgari O02 işlemi: [mevcut sağlık sorgusunu](../scripts/ops-cron-health.sql) çalıştır → enabled/stale/error ayrımını incele → seçilmiş mevcut e-posta kanalından tarihli teknik alarmı ilet → gerçek worker kimliği/scope/son tick sorununa müdahale et → aynı sorguyla sağlığı yeniden oku → toparlanmayı ilet ve alıcıya teslimi doğrula. Kontrollü test ile canlı olay açıkça ayrılır; testten sonra özgün ayarlar geri yüklenir. Yeni daimi host, izleyici veya ayrı alarm servisi kurulumu gerekmez. Gerçek kabul sonucu [tek durum sahibindedir](00-FtkSaaS-yeni-sohbet-devir.md#o02-alarm-cekirdegi).

Aşağıdaki [operator değerlendirmesi](../scripts/ops-monitor.mjs), [kalıcı gönderim döngüsü](../scripts/ops-monitor-outbox.mjs) ve collector açıklamaları yazılmış araçların teknik referansıdır; bu teslimde sürekli işletim kurulumu veya backup alarmı önkoşulu oluşturmaz. Araçlar frontend/native kullanıcı API'si değildir. Geniş otomatik izleme hedefleri [Business sonrası altyapı kapsamındadır](../../../docs/contracts/02-FtkSaaS-teknik-sozlesme.md#20-kabul-edilmiş-o3-pilot-işletim-hedefleri).

[Collector](../scripts/ops-monitor-collector.mjs), özel native `ftk_ops_monitor` bağlantısında yalnız `ops_monitor.snapshot()` çağırır. Yeni monitor şeması public API şeması değildir; role private/core/Auth tablo veya worker yetkisi verilmez. Native `session_user` eşliği zorunludur. Monitor rol parolası migration'da seçilmez; bağlantı/TLS/secret ve sürekli dış host kurulumu ayrıca ortam girdisidir. Sağlık sonucu yalnız lane/enabled/tarih/status ve toplu job sayaçları taşır. Provider retleri yalnız backend job'unun sahip olduğu referansla sayılır; aynı job'un terminal state'i ve provider olayı iki kez sayılmaz. Worker kritik hatası ayrı teknik UUIDv7 kaydıdır; sonraki idle heartbeat geçmiş kanıtı silmez. Bu kayıt bütün Edge hatalarının merkezi kabulü yerine geçmez.

Collector `readerTimeoutMs` girdisini zorunlu alır; DB, backup ve dış probe okumalarının her biri sınırlanır ve iptal sinyali alır. Native okuyucu timeout'ta dedicated bağlantısını kapatır; bağlantı kurma aşamasını çağıran adaptör ayrıca sınırlamalıdır. DB gözlemi yokken önceki worker/job olayları kapanmaz ve dış erişim hatası sayılır. Backup okuması başarısızsa `unavailable` gözlemi üretilir; yedek sağlam veya kayıp varsayılmaz ve diğer alarm okumaları durmaz. Terminal/kritik geçmişi silerek alarm susturma yapılmaz. [Operatör teyidi](../scripts/ops-monitor-ack.mjs), snapshot'taki güncel teknik SHA anahtarları ve `monitorReviewToken` ile incelemeye bağlanır. `runOperatorMonitor` yalnız açık `acknowledge={expectedSnapshot,exhausted,integrity}` isteğinde seçili bilinen anahtarları özel state'e kaydeder; sürekli döngü otomatik teyit vermez. Değişmiş snapshot, bilinmeyen anahtar veya DB kesintisinde teyit reddedilir. Teyit `acknowledged` olayıdır; `recovery` veya işin tamir edildiği anlamına gelmez. İş/event satırları değişmez; farklı job sürümü veya yeni kritik event yeni anahtar ve alarm üretir. Snapshot tür başına en fazla1000 teknik anahtar, ayrıca tam toplamı döndürür; kısıtlı sayfanın dışındaki bilinmeyen kayıtlar teyitle sıfırlanamaz. Kalabalık/açık incident incelemesinde toplam ile sayfa kapsamını birlikte değerlendir; eski state'i silme. Gerçek işletim teyidi/teslim kabulü backend kabul sahibindedir.

`runOperatorMonitor` açık `directory`, `observation`, `mail` ve `policy` alır. Mail alıcısı/göndericisi/API anahtarı ve tekrar politikası runtime girdileridir; test fixture değerleri kurulum varsayılanı değildir. Dedicated state dizini sahibi çalıştıran kullanıcı, izinleri0700; state ve lock0600 olmalıdır. Dizin izlenen DB'den bağımsız kalıcı diskte tutulur. Snapshot/state ve posta olayı atomik/fsync sınırından sonra mevcut Resend transport'una gider. Alıcı, gönderici, içerik, idempotency anahtarı ve politika pending olay için sabittir; API anahtarı dosyaya yazılmaz. Tekrar sayısı/aralığı açık seçilir; sağlayıcı anahtarının güvenli penceresi23saati aşamaz. State alıcı içerdiğinden özel işletim verisidir, kaynak veya rapora kopyalanmaz. Bu araç tek döngü çalıştırır; kendisi cron/host kurmaz.

- `worker:*`: önce [read-only sağlık sorgusunda](../scripts/ops-cron-health.sql) enabled ve gerçek Cron owner/active/schedule bilgilerini kontrol et. Kapalı worker toparlanmış sayılmaz. Enabled/stale ise gerçek LOGIN, scope ve son tick/lease durumunu incele; kullanıcının onayı olmadan tenant scope icat etme.
- `jobs:stuck`, `jobs:exhausted`, `jobs:integrity`: ilgili mevcut job/receipt ve lane teşhisini kullan. İşlemi veya tahsilatı körlemesine tekrarlama; bütünlük ihlalinde ilgili işlem güvenli biçimde durmalıdır. Başarısız geçmiş kayıtlarını yalnız alarmı susturmak için silme.
- `backup`: son kullanılabilir DB/Auth/Storage kurtarma noktası ve bağımsız manifesti doğrula. Eksik/bozuk/gecikmiş yedeği sağlıklı olarak işaretleme; restore kabulü kendi kapılarındadır.
- `rejected`, `exhausted`, `expired`: provider/reference ve gönderim yapılandırmasını yetkili SaaS işletim sorumlusu inceler. `accepted`, yalnız sağlayıcı kabulüdür; teslimi sağlayıcı olayı veya yetkili alıcı kutusunda ayrıca doğrula. Ham sağlayıcı mesajını/credential'ı loglama. Güvenli pencere dışındaki belirsiz olayı yeni anahtarla otomatik gönderme.
- `MONITOR_LOCKED`: önce önceki sürecin gerçekten bittiğini doğrula. Lock yaşından/PID numarasından otomatik ölüm sonucu çıkarma. State'i silerek yeniden başlatma; pending/sending olayları koru ve olası provider kabulünü uzlaştır. Yapılandırma veya state bozulmasında araç kapalı hata verir; sahte toparlanma üretme.

Alarmın ulaşması müdahale edildiğini kanıtlamaz. Gerçek fault→teslim→müdahale→toparlanma kabulü ve sürekli gözlemci kurulumunun durumu [backend kabul sahibindedir](00-FtkSaaS-yeni-sohbet-devir.md#o02-alarm-cekirdegi).
