# CI çalışma politikası

Bu bölüm kullanıcının 28 Ekim 2026 sadeleştirme kararını tarif eder; önceki otomatik targeted, etiketle aday clean ve merge sonrası test tekrarı hükümlerinin yerini alır. Kurulum/kabul durumu yalnız [00 devirde](../apps/backend/docs/00-FtkSaaS-yeni-sohbet-devir.md), açık iş [backlog’da](../apps/backend/docs/remaining-work.md) tutulur. Geçmiş koşular yeni kaynak için kanıt değildir.

## Olaylar ve kabul

| Olay | Gerekli işlem |
|---|---|
| Main tabanlı PR açma, kaynak güncelleme, yeniden açma veya main’e retarget | `Backend CI` önce base→head tam ağaç farkını sınıflandırır. Backend/shared kapsamda olayın sabit merge SHA’sında core + on iki API shard + toplayıcı; saf belgede yalnız belge kontrolü; frontend-only kapsamda backend testi yok. |
| Draft PR | Aynı otomatik test kapsamı çalışabilir; merge kapısı kapalıdır. Hazır duruma geçiş testleri tekrar başlatmaz, mevcut kaynak kanıtını değerlendirir. `development` etiketi artık test/merge kontrolü değildir. |
| PR başlığı/açıklaması/etiketi | Test tetiklemez; GitHub `edited` olayını retarget ile ortak ilettiği için başlık/açıklama olayının workflow zarfı görünebilir, bütün işler atlanır. Eski `ci:full-clean` ve `ci:measure-serial` etiketlerinin kabul yetkisi yoktur. |
| PR dışındaki branch push | Otomatik backend testi yok. |
| Main merge | `Main acceptance` gerçek merge parent/tree ve adayın başarılı run/attempt/job kanıtını doğrular. Aynı full clean veya belge testini tekrarlamaz. |
| Main kabulü tamamlandı | `Development delivery` yalnız doğrulanmış backend kabulünü development ortamına taşır ve hosted kontrolleri çalıştırır. Production yetkisi yoktur. |
| Manuel tanı | `Manual targeted`, yalnız main’den seçilen tam `base_sha`→`tested_sha` aralığını test eder; merge/full/main kabulü veya status üretmez. |

Metadata olayları ayrı concurrency grubundadır; çalışan veya bekleyen kaynak full clean’ini iptal edemez. Aynı PR’nin eski kaynak koşusu iptal edilir; farklı PR ve main kabulü birbirini kesmez. Otomatik PR testinden önce ayrıca targeted koşulmaz. Base retarget gerçek yeni kabul gerektirir; başlık/açıklama/etiket olayları full clean yaratmaz. Yetkili merge doğrulayıcısı kaynak sonucu tamamlandığında ve Draft/hazır durum değişiminde çalışır; PR açılışı/synchronize için ayrıca aynı doğrulamayı başlatmaz. Main değişimi açık PR’lerin kanıtını yeniden değerlendirir. Workflow’nun yeşil olması tek başına required status’un başarılı olduğunu göstermez.

## CI-SPLIT — frontend/backend kaynak sınırı

[Pozitif kaynak kaydı](../apps/backend/scripts/ci/scope.json) backend/shared girdileri, incelenmiş belge listesini ve frontend sahipliğini ayırır. Aday test kapsamları bu kayda göre seçilir. Ortak Main acceptance kapısı yol filtresi olmadan her main push için çalışır. Bütün workflow dosyaları backend politika güven yüzeyidir; yeni/silinen workflow belgesel istisna sayılmaz. Frontend workflow’ları frontend test kapsamındadır ama politika kurulum kontrolünden muaf değildir. Bilinmeyen diğer yol, eksik/truncated ağaç veya boş fark başarılı atlama değildir.

`.agents/**` yalnız ajan talimatı/yerel araç alanıdır; uygulama, ürün belgesi veya runtime yapılandırması değildir. Tek başına değiştiğinde `agents` kapsamı kalite/secret taraması ve tam head/base/merge-tree kanıtını korur; backend DB/API/full clean, frontend uygulama testi veya dağıtım başlatmaz. Ürün belge sahipliği ve bağlantı kabulü bu alanı taramaz; genel tracked environment-secret koruması sürer. Karma farkta backend/shared tam kabulü, frontend kendi kabulünü, incelenmiş ürün belgeleri belge kabulünü korur. Taşıma/silmenin iki ucu incelenir; uygulamadan bu alana taşıma eski uygulama kaynağını kabul dışına çıkarmaz. Bu alandaki yerel araç config'leri uygulama CI politikasını kuramaz; gerçek workflow ve backend CI kaynaklarının trusted kuralları değişmez.

Frontend sahipliği `apps/web/**`, `packages/ui/**` ve kayıtlı iki frontend workflow’udur. Frontend-only main değişikliği backend test/CD tetiklemez. Frontend+belge değişikliği gerçek belge kabulü ister. Backend+frontend/belge karmasında backend’in bütün kapsamı korunur. Rename/silmenin iki ucu ve mode değişimi değerlendirilir. Ortak API/TypeScript paketi, root manifest/lock/workspace, Turbo ve Node girdileri shared kapsamdır; frontend lock importer’ı için örtük istisna yoktur.

Buradaki sahiplik test seçimi içindir; ajana yazma yetkisi vermez. Seçici kullanıcı görevinin frontend/backend sınırını doğrulamaz: frontend kodu ile kök belge içeren bir diff uygun testlerle geçebilir. Belge kaydı da dosya/konu tutarlılığını denetler, değişikliği yapan ajanın görev yetkisini değil. Görev kapsamı kök [belge yazma sınırına](../AGENTS.md#belge-yazma-sınırı) göre commit/PR öncesi ve bağımsız incelemede ayrıca kontrol edilir; bu kontrol mevcut CI tarafından otomatik engelleniyormuş gibi raporlanmaz.

Backend verify yalnız `--filter=@ftksaas/backend...` Turbo grafiğini yürütür. Frontend status’u frontend testlerinin yerine geçmez; frontend kendi gerçek test/workflow kabulünün sahibidir. İki zincirin gerçek tek-taraflı ve ortak kaynak örnekleriyle kabulü ayrıca kanıtlanır; yerel sentetik grafik testi uzak kabul sayılmaz.

İki frontend workflow'u main tabanlı PR kaynak olaylarında, ortak Main acceptance kapısı da main push'ta önce dependency kurmadan [kapsam seçicisini](../apps/web/scripts/ci-scope.mjs) çalıştırır. Üst düzey yol filtresi kullanılmaz; büyük farklarda GitHub'ın sınırlı olay diff'i gerekli işi atlayamaz. Başlık/açıklama değişikliği bütün işleri atlar ve ayrı metadata concurrency grubu çalışan kaynak testini iptal etmez; main'e retarget yeni seçim yapar. PR'de event'in base/head parent'ları doğrulanan gerçek merge ağacı, main push'ta event'in tam before→after aralığı kullanılır; checkout SHA eşleşmesi zorunludur. Tam Git farkında silme/taşımanın iki ucu ve mode değerlendirilir. Aynı incelenmiş belge kaydındaki yalnız regular100644, geçerli UTF8 ve NUL içermeyen dosyalar ağır frontend işlerinden muaftır; genel `.md`/`docs/**` istisnası yoktur. Belge-only değişimde build, coverage ve tarayıcı işleri atlanır; bu atlama test kabulü olarak sunulmaz. Belge bağlantı/içerik kabulü mevcut backend belge zincirinin sorumluluğunda kalır.

Frontend kodu, ortak UI veya kendi workflow'u `checks` ve refactoring süresince yalnız Desktop Chromium'un üç shard'ını; ortak API/TypeScript paketi, root dependency/lock/workspace/Turbo/Node girdileri veya compatibility workflow'u typecheck ve isolation kontrolünü seçer. Karma fark gereken kapsamların birleşimidir. Seçici, kapsam testi veya belge izin listesindeki değişiklik iki zinciri de seçer; makine sözleşmeleri belge muafiyeti almaz. Yeni/kayıtsız frontend belgesi ilk değişiminde normal frontend kapsamını çalıştırır. Manuel frontend çalıştırması tam ilgili zinciri seçer; boş fark muhafazakâr olarak iki kapsamı da açar, eksik/geçersiz kaynak veya okunamayan fark açık hatadır.

Frontend testleri PR adayında veya manuel tanıda yürütülür. Aday kaynak olayında tarayıcı görevi doğrulanmış base ve merge SHA ile Turbo `--affected` kullanır. [Kapsam seçicisi](../apps/web/scripts/ci-scope.mjs) incelenmiş özellik veya bağımsız spec değişikliğinde giriş ve statik derleme testlerine ilgili spec'leri ekler. Ortak fixture, UI, uygulama altyapısı ve eşlenmemiş kaynak değişikliği tam paketi seçer. İncelemeye hazır olayında ve manuel çalıştırmada tam paket seçilir.

22 Kasım 2026 geçici refactoring kararı: otomatik tarayıcı kabul matrisi yalnız **Desktop Chromium (Desktop Chrome)** üzerinde üç Playwright shard'ı çalıştırır (`ubuntu-24.04`). Seçilen veya tam test envanterinin üç shard'a eksiksiz ve tekrarsız bölünmesi, kaynak/rapor ve build artifact doğrulaması zorunludur. Mobile Chromium (Pixel 7), Desktop WebKit (Desktop Safari) ve Mobile WebKit (iPhone 14) **refactoring tamamlanana dek otomatik CI planına dahil değildir**; profil tanımları, senaryolar ve assertion'lar silinmez. Bu dönemin başarılı sonucu yalnız Desktop Chromium kabulünü kanıtlar, dört tarayıcı kabulü sayılmaz. Refactoring tamamlandığında aynı trusted politika kurulum süreciyle dört profil × üç shard (12 iş) zorunlu kabule geri alınır. Mobile WebKit'in o dönemdeki runner'ı `macos-26`, diğer profillerin runner'ı `ubuntu-24.04` olur. Gerçek cihaz kabulü ayrıca yürütülür.

Tek ortak [Main acceptance](../.github/workflows/backend.yml) kapısı bütün main push olaylarında çalışır. Ortak kapı gerekli frontend test kanıtı ile mevcut backend ve belge kanıtlarını birlikte doğrular. Sözleşme compatibility kontrolü PR ve manuel tanı sinyalidir. Backend'in bağımsız teslimi ve main kabulü compatibility sonucuna bağlı değildir. Main push, kapsam gerekiyorsa [frontend kanıt doğrulayıcısı](../apps/web/scripts/ci-proof.mjs) ile aynı depodaki başarılı PR koşusunun kaynak makbuzunu doğrular. Normal merge'in base/head parent'ları ve tam dosya ağacı adayla eşleşmelidir. Seçili spec listesi veya tam paket kapsamı ile refactoring döneminin **üç Desktop Chromium shard'ı dahil bütün zorunlu işler** ve adımlar güncel attempt görünümünde doğrulanır. Yalnız aktif politika matrisine ait başarı kabul edilir; başka profilin atlanması dört profilin başarıyla kabul edildiği anlamına gelmez. Rerun'da devralınan makbuz kendi source attempt'ine bağlı kalır. Okuma sonunda run yeniden doğrulanır. Eksik veya süresi dolmuş makbuz, iptal veya başarısız iş, atlanan zorunlu iş, squash/rebase, toplu push ve değişmiş kaynak açık hatadır. Main aynı testleri tekrar çalıştırmaz. Workflow değişiklikleri aşağıdaki trusted politika kurulum şartlarına tabidir.

Frontend `checks` işi lint/typecheck, tek coverage koşusu ve tek production build yapar. Tarayıcı shard'ları aynı koşudaki artifact kimliği ve SHA256 ile doğrulanan derleme çıktısını kullanır. Build kaynağı, run/üretim attempt'i, Node, üretici platformu ve mimarisi ile build girdileri doğrulanır. Mobil WebKit yeniden etkinleştirildiğinde macOS ARM64 üzerinde Ubuntu x64 üreticisinin aynı statik derlemesini doğrular. Başarılı üretici işini devralan shard, rerun'da aynı artifact'ı kullanır. Eksik veya uyuşmayan artifact kabulü durdurur. Yerel `check:frontend` geliştirme komutu korunur.

## Ortak kalite kanıtı

[Kalite sözleşmesindeki](../CONSTRAINTS.md) floor ve secret kontrolü her kaynak PR’sinde `Backend CI / quality` işinde çalışır; işin araç sahibi backend, kapsamı iki alandır. Saf belgede dependency/DB/API/build kurulmaz. Frontend-only kaynakta backend full clean gerekmez, fakat ortak kalite kanıtı gerekir. Kalite kanıtı frontend contract compatibility veya frontend’in backend’e adapte olmasını bekleyen bir kapı değildir.

Kalite işi olayın tam merge SHA/parent/tree’sini doğrular. Salt-okuma token ile floor/olumsuz senaryolar ve sabit checksum’lu Gitleaks yeni base→head commit aralığını denetler. Başarılı adımlardan sonra run’a özel `quality-binding` makbuzu yüklenir. Trusted merge/main doğrulayıcısı mevcut head/base/tree/run ve güncel attempt job/step başarısını, ardından canlı run durumunu doğrular. Failed-job rerun’da kaynak makbuzu eski attempt’ten devralınabilir; yanlış kaynak veya atlanan secret adımı başarı sayılmaz. Main tekrar tarama yapmaz.

Kalite sözleşmesi, checker/istisna dosyaları, uygulama/root görev manifestleri, Turbo, frontend/UI lint ve coverage config’leri ile TypeScript/Playwright config’leri (yeni iç klasör config’leri dahil) trusted politika karşılaştırmasına dahildir. Kurulum değişiklikleri mevcut kaynak-özel inceleme/kurulum prosedürünü izler; yeni status veya bypass mekanizması eklenmez. Yerel `pnpm check:quality` Turbo üzerinden çalışır; Git farkına bağlı görev cache kullanmaz. Bütçe ve ölçülmemiş boyutların tek sahibi CONSTRAINTS’tir.

## Manuel tam koşu

`Backend CI` içindeki `workflow_dispatch`, yalnız main’den tam40 karakter `tested_sha` ile yeni bir tanısal full clean başlatır. Workflow ve planlama/toplayıcı kodu dispatch olayının sabit main SHA’sından gelir; hedef commit’in envanteri güvenilir parser ile Git blob/mode/hash ve kaynak sahipliği denetlenerek veri olarak okunur. İlk denemede son uygun başarılı PR koşusunun ölçümleriyle yeni plan üretilir; core ve on iki API shard aynı tam hedef SHA/tree ve planla çalışır. Test runner’ı hedef commit’teki mevcut clean protokolüyle uyumlu olmalıdır; uyumsuzluk açık hata verir. PR kapsam seçimi, kalite kabulü ve otomatik CI/CD yolu değişmez.

Manuel koşular PR’lerden ayrı concurrency grubundadır. `manual-source` ilk planı korur; rerun aynı workflow/hedef/tree/envanter/run kaydını ve planı kullanır, yeni ölçüm seçmez. Yeniden dağıtım için yeni `Run workflow` gerekir. `manual-full-binding-ATTEMPT` yalnız tanı raporudur; candidate/main kabul artifact’ı, merge status’u veya deploy yetkisi üretmez. Manuel ölçümler otomatik PR süre referansı havuzuna katılmaz. Rapor gerçek test sürelerini backend kurulumu ve kuyruktan ayırır; en uzun/en kısa oranı1,20 hedefi yalnız uyarıdır, işlev testinin yerine geçmez veya merge’i engellemez.

## Manuel targeted

Girdiler tam 40 karakter SHA’dır; base test edilen head’in atası ve checkout birebir head olmalıdır. Son commit için parent→commit, birikimli değişiklik için seçilen ancestor→head kullanılır; origin/main merge-base’i açık aralığın yerine geçmez. Plan ve shard çıktıları kaynak aralığını gösterir; bu tanı mevcut main ile birleşim uygunluğunu kanıtlamaz.

Seçici güvenilir main kodundan çalışır. Kaynak–tüketici ve append-only migration kanıtıyla ilgili API suite’lerini seçer; eksik/açıklanamayan runtime farkı geniş regresyona gider. [Delta analizi](../apps/backend/scripts/ci/delta-analysis.mjs) ortak Auth/tenant/finans/hak/gateway değişikliğini dar modüle sahiplenmez. Kaynağın API envanteri trusted envanterden farklıysa yeni/silinmiş test sessizce atlanmaz; tanı açık hata verir, önce incelenmiş envanter kurulmalıdır.

Seçilen API suite’leri mevcut ölçümlü dört shard planının kesişimine dağıtılır; boş shard açılmaz. Her API shard ayrı runner/backend/DB kullanır; concurrency=2 korunur. İlgili öncelikli test hata verirse aynı shard’daki ertelenmiş regresyon başlamaz. Core/DB ve API işleri ayrı runner kullanır. Belge/frontend-only tanı dependency kurulumu veya DB/API başlatmaz. Plan/timings artifact’leri tanıdır; source-bound kabul makbuzu değildir.

## Güvenli belge kabulü

İncelenmiş tam yol, regular100644 dosya ve UTF8/NUL kontrolü gerekir; `.md`, `docs/` veya etiket yeterli değildir. Workflow, seçici/kapı, dependency/lockfile, migration, makine sözleşmesi ve runtime tipleri istisna değildir. Eski renderer’ın üç incelenmiş açıklama slotu yalnız kendi AST bağlamında belge kanıtı alabilir. Yeni renderer bu istisnayı devralmaz; üreteçteki bütün değişiklikler tam kapsama gider. [Renderer kanıtlayıcısı](../apps/backend/scripts/ci/renderer-proof.py) dosyanın tamamına izin vermez.

PR’nin gerçek merge ağacında [belge kontrolü](../apps/backend/scripts/ci/docs-check.mjs) yaşayan inbound/outgoing bağlantıları ve anchor’ları denetler. Belge-only iş dependency/backend kurulumu yapmaz; DB/API/full clean gibi raporlanmaz. Main aynı parent/tree ve receipt’i doğrular; kontrol tekrarı yoktur. Ayrı eski belge workflow’u ve recovery girişi kaldırılmıştır. Eski başarısız run değiştirilmez; sorun düzeltildiyse yeni gerçek kaynak kanıtı gerekir.

## Tam clean ve kanıt doğrulama

İzole yerel/CI takvim fixture’ı `FTK_CALENDAR_DIAGNOSTICS=1` ile native takvim503 yanıtında yalnız sabit hata aşaması, upstream HTTP durumu ve izinli worker hata kodunu açar. Hosted yapılandırmaya eklenmez; varsayılan kapalıdır. Kabul testi başarısız isteğin metodunu ve süresini bu sınıflarla kaydeder; URL, takvim credential’ı, upstream gövdesi ve özel hata metni raporlanmaz. HTTP200 beklentisi, süre sınırları ve paralellik korunur; bu tanı kök nedenin çözüldüğü veya canlı kabul verildiği anlamına gelmez.

[Ortak clean suite](../.github/workflows/clean-suite.yml) yalnız adayda çalışır. Core ve on iki API işi ayrı runner/backend/DB’de temiz migration manifesti ve boş Auth/tenant/receipt ile başlar. Core verify/DB/seed/health/advisors’ı, on iki shard bütün API parçalarını eksiksiz ve tekrarsız taşır. Test gövdelerindeki yarışlar bölünmez; fail-fast:false korunur. Normal parçalar concurrency=2, global fixture yazan parçalar ayrı concurrency=1 fazında çalışır. Üretim envanteri ve parça yükleyicisi `apps/backend/scripts/ci/api-suites.json` ve `api-suites.mjs` sahibindedir; üretim runner’ı deney dizininden kod yüklemez. API job üst sınırı 90 dakikadır; kök/alt testlerde kaynakta tanımlı timeout’lar, istek/SQL deadline’ları ve 3 GiB Edge RSS koruması korunur. Backend clean, targeted ve CD işleri sabit pnpm ile `corepack enable` ve `pnpm --filter @ftksaas/backend... --filter ftksaas install --frozen-lockfile` kullanır; root Turbo ve backend bağımlılıkları kurulur, web/UI runtime bağımlılıkları kurulmaz.

[Toplayıcı](../apps/backend/scripts/ci/collect.mjs), aynı run’ın güncel deneme görünümündeki bütün zorunlu job/step sonuçlarını GitHub API’den doğrular. GitHub’ın failed-job rerun sırasında koruduğu başarılı işler kabul edilir; geçmiş denemelerden elle başarılı iş seçilmez. Güncel görünümde skipped/cancelled/failure/eksik/mükerrer iş veya çalışmamış kaynak/test/baseline-upload adımı kabulü kapatır. Artifact tek başına başarı değildir.

Aday çözümleme değişebilen PR merge ref’i yerine ilk olayın `GITHUB_SHA`, base ve head değerlerine sabittir. Base/head değişmişse yeni koşu gerekir. `twelve-timed-v1` makbuzu PR/head/base/merge/tree/run/coverage bağlarını, kaynak çözümleme denemesini (`source_attempt`) ve kabul denemesini (`attempt`) ayrı taşır. GitHub’ın devralınmış işler için güncel deneme numarası ve yeni job ID vermesi yeniden fiziksel yürütme anlamına gelmez; ölçüm gerçek yürütme zamanlarını saklar. Toplayıcı ve merge/main/CD doğrulayıcısı okuma sonunda canlı run/attempt durumunu yeniden kontrol eder. Geçmiş `four-isolated-v1`/`four-isolated-v2` dört shard ve `eight-isolated-v1` sekiz shard ve `twelve-isolated-v1` sabit on iki shard makbuzlarının kendi rol doğrulaması korunur; yeni kaynak sabitleme garantisi geçmişe varsayılmaz.

Toplayıcı-only rerun yalnız aynı kaynakta bütün zorunlu işler başarılıysa kabul makbuzunu yeniler. Başarısız API job’ı eski bir başarıyla kapatılamaz. Kanıt seçimi her başarılı koşuyu bağımsız doğrular; iptal edilmiş, eski veya makbuzu eksik başka koşu geçerli kanıtı gölgelemez. Kaynak uyumsuzluğu yine kabul edilmez.

Merge normal iki parent’lı merge olmalıdır; squash/rebase’e kanıt taşınmaz. Head/base/tree değişirse yeni kabul gerekir. Main yeniden test yerine gerçek parent/tree’nin test edilen adayla aynılığını ve başarılı adayın güncel attempt/job sonuçlarını doğrular. Böylece test maliyeti tekrarlanmaz; kaynak güveni kaldırılmaz.

İnceleme tamamlandıktan sonra GitHub’ın yerleşik auto-merge özelliği PR üzerinde **merge commit** yöntemiyle etkinleştirilir; CI bitene kadar elle beklemek gerekmez. Açık, Draft olmayan PR’nin incelenmiş güncel head SHA’sı doğrulanır. Auto-merge etkinleştirme inceleme onayı veya başarılı status üretmez; gerekli CI, kaynak kanıtı, review ve trusted politika kurulum şartları korunur. Sonraki kaynak değişikliği yeniden inceleme gerektirir; auto-merge beklerken kaynak güncellemesi yapılacaksa auto-merge önce kapatılır. Ek ayrıcalıklı bot workflow’u, otomatik approval veya bypass kullanılmaz.

[Dependabot](../.github/dependabot.yml) başlangıçta yalnız GitHub Actions minor/patch güncellemelerini haftalık, 7 günlük bekleme ve tek grup ile önerir; en fazla iki açık güncelleme PR’ı vardır. Major güncellemeler ve uygulama paketleri bu otomasyonun dışındadır. Dependabot PR’ları da inceleme sonrası aynı auto-merge akışını kullanır; bot adına otomatik approval veya workflow politika muafiyeti yoktur.

## API süre dengesi — uyarı ve ölçüm

28 Ekim üretim önceliği kararı önceki zorunlu süre kapısını kaldırır. Süre dengesi fonksiyon doğruluğu veya güvenlik kabulü değildir. On iki API gerçek `Clean acceptance` süreleri her koşuda raporlanır; oran1.25 ve fark120sn birlikte aşılırsa GitHub uyarısı oluşur. Eksik/geçersiz ölçüm de görünür uyarıdır. Bu durumlar kendi başlarına full clean, merge veya development CD’yi engellemez; eşikler artırılarak yeşil sonuç üretilmez, optimizasyon üretim dışında değerlendirilir.

Toplayıcı önce kaynak/run/attempt/coverage ve bütün zorunlu core/on iki API gerçek test başarılarını doğrular. Bunlardan biri eksik/skipped/cancelled/failed veya başka run/head’e veya güncel deneme görünümü dışına aitse binding üretilmez. Bu güvenlik sınırı değişmez. Sonra süre ölçümü ayrı try/catch içinde değerlendirilir; rapor ve varsa uyarı yazılır, fonksiyon/kaynak kabulü başarılıysa binding üretilir. Binding `balance_mode:advisory` taşır; süre politika sürümü veya denge sonucu trusted merge/main/CD kapısının kabul şartı değildir.

Yeni testler eksiksiz suite/parça envanterinde bulunur; kaynak hash’i ve satır sahipliği denetimleri eksik, mükerrer veya değişmiş gövdede kabulü durdurur. Kullanıcının on iki shard’a geçiş kararıyla mevcut bölünmüş envanter üretim kabulünde on iki runner’a dağıtılır. Shard sayısı profile ve coverage hash’ine bağlıdır; API-9–API-12 dahil her zorunlu iş kaynak/run/attempt ve başarılı test adımlarıyla doğrulanır. Geçmiş dört shard planı yalnız tarihsel kanıt ve manuel hedefli suite kesişimleri için korunur. İşlevsel kapsam, test assertion’ları ve kaynak güvenliği gevşetilmez. Failed-job rerun kabulü yukarıdaki sabit kaynak ve güncel GitHub job görünümüne dayanır. İncelemede açıkça istenen attempt API’si kullanılır; güncel görünüm geçmiş denemede yeniden çalıştırılmış test gibi sunulmaz.

Üretim `twelve-timed-v1` adayı başlangıçta son 20 başarılı Backend CI koşusu içinde tamamlanma zamanına göre en yeni uygun `api-duration-reference-ATTEMPT` artifact’ını seçer. Run’ın güncel success/attempt/head durumu, aday makbuzu, gerçek merge parent/tree ve core/on iki API/toplayıcı kaynak/adım başarıları doğrulanır. Gövde SHA256’sı eşleşen tamamlanmış process-wall süreleri kullanılır. Referans yoksa/expired ise veya servis/ölçüm okunamazsa görünür uyarıyla repodaki kaynak snapshot’ına dönülür; değişmiş gövdeler mevcut kaynak boyutu tahminini kullanır. Ölçüm eksikliği fonksiyon kabulünün yerini tutmaz ve tek başına onu engellemez.

Seçilen ağırlıklar, referans run/attempt/head/merge/tree izi, tam parça dağılımı ve bunların SHA256’sı aday binding’inde sabitlenir. İlk denemenin `candidate-source` artifact’ı bu binding’i korur. Candidate işi de dahil her rerun aynı artifact’tan ilk planı alır; son süreleri yeniden seçmez. Bu kaynak artifact’ı eksik/expired veya head/base/merge/run ile uyumsuzsa yeni koşu gerekir; yeni planla devralınmış işler birleştirilmez. Bütün shard’lar aynı binding’i doğrular; toplayıcı, merge/main/CD doğrulaması tam envanter ve plan hash’ini kontrol eder. Main test tekrarlamaz. Tek bir parçaya özel runner tahsisi yoktur.

Her materialized native süreç, API isteği yapmayan SQL birimleri dahil, kendi gövde hash’i ve çıkış koduyla süreç süresini kaydeder. Başarılı zorunlu işlerden sonra toplayıcı aynı run’ın her shard’ında en son üretilmiş deneme artifact’ını okur; devralınmış başarı kendi yürütme denemesini korur. Eksik/bozuk/sıfır/başarısız ölçüm veya farklı kaynak/plan/deneme varsa yeni referans yayımlanmaz, uyarı verilir. Tam ölçüm `api-duration-reference-ATTEMPT` olur; yalnız bütün workflow başarıyla tamamlandıktan sonra sonraki aday için seçilebilir. Başarısız koşu eski başarıyı güncellemez. Kaynağa otomatik commit veya yeni ayrı workflow eklenmez; artifact saklama süresi 90 gündür.

## Sekiz shard karşılaştırma deneyi

[Backend experiment](../.github/workflows/backend-experiment.yml) yalnız kurulu main workflow'undan manuel başlatılır. Girdi, mevcut Backend CI'ın başarılı full-clean PR koşu kimliğidir. Referansın candidate ve quality makbuzları, tam head/base/merge/tree, güncel attempt ve zorunlu job/step başarıları doğrulanır; başarısız/eksik belge veya yalnız frontend koşusu referans olamaz. Deney tanımı ile test edilen kaynak ayrı SHA'larla kaydedilir. Referansın tam merge kaynağı ayrı checkout'a alınır; ürün kodu, migration, paket/lockfile, Node ve Supabase sürümleri o kaynaktan gelir.

[Ortak parça envanteri](../apps/backend/scripts/ci/api-suites.json) özgün test dosyalarını değiştirmez. Kaynak hash'i ve açık satır aralıkları her parçanın sahibini gösterir; değişmiş dosya, eksik/mükerrer aralık veya yeni/kayıp suite deney başlamadan reddedilir. Bağımsız kabul modülleri ve tam test kökleri ayrılır; iptal senaryoları para, paket, planlı zaman, gerçek başlangıç ve uzlaşma/yarış gruplarına bölünür. Ortak hazırlık ve finally temizliği korunur; yarış senaryosunun gövdesi bölünmez. Geçici ESM yükleme kancası yalnız seçilen özgün modülün gövdesini değiştirir; özgün URL, göreli import ve import.meta.url korunur. Test gövdeleri ikinci kez elle yazılmaz. Tam gövde derleme ve gerçek modül yükleme eşdeğerliği deneyin ön kontrolündedir. Bir import modülündeki bağımsız native kökler de aynı açık shared/parts satır sahipliğiyle ayrı deney birimlerine alınabilir. Her parça kendi fixture fonksiyonuyla yeni tenant ve bağlantı kurar; önceki kökün sonucunu devralmaz. Global platform settings sürümünü yazan tenant yetkisi ve typed katalog kökleri aynı dosya biriminde özgün sırayla tutulur.

Sekiz API runner'ı ayrı native backend/DB kullanır. `oneshot`, temiz migration/boş Auth/tenant/receipt ve 3 GiB bellek koruması korunur. Normal parçalar runner içinde concurrency2 kullanır; singleton güvenlik/worker/dispatch ayarlarını değiştiren beş açık parça kendi runner'ında diğer dosyalarla çakışmadan ayrı fazda yürütülür. Bu sınır test gövdesindeki gerçek yarışları seri hale getirmez. ST-02 için tek runner tahsisi kaldırılmıştır; bu akış da sekiz runner'ın ortak dağıtımına girer. Tamamlanmış parça process-wall süreleri run/attempt/job ve gövde SHA256 iziyle yalnız planlama girdisidir. Kaynak hash'i eşleşmeyen veya tamamlanmış ölçümü olmayan parça açıkça kaynak boyutu tahmini kullanır; timeout ile kesilen parça tamamlanmış ölçüm sayılmaz. Planlayıcı ayrı fixture fazlarını ve normal testlerin iki yürütme hattını hesaba katar. Parçalanmamış en uzun kök planlanan sürenin alt sınırıdır; dengeli tahmin gerçek hız kazancı değildir.

Ölçüm deneyinde yalnız API test kaydı sınırındaki kök ve alt test `timeout` seçenekleri native `Infinity` ile geçersiz kılınır. ESM çözümleme kancası yalnız kaynak test dizinindeki `node:test` importlarını deney adapter'ına yönlendirir; özgün dosyalar, assertion ve kaynak gövdeleri değişmez. Üretim materialize yolu ve sekiz shard kabulü özgün timeout'larla kalır. Tek istek/SQL/kaynak kapatma deadline'ları, hata yayılımı, temizlik ve bellek koruması korunur. Core ve API job üst sınırı90 dakikadır; sonsuz bekleme yoktur. Kök/alt test sonuçları ve süreleri hata mesajı/payload taşımayan JSONL artifact'ına yazılır; fixture/API zamanları mevcut ölçümden gelir. Timeout politikaları farklı olduğundan başarılı ölçüm, referansla aynı süre kabulü veya merge kanıtı değildir.

Core özgün clean komutunu çalıştırır. Ayrı toplayıcı bütün deney işlerinin aynı kaynak ve güncel attempt'te başarılarını, referansın hâlâ aynı başarılı attempt olmasını doğrular. Kapsam planı, gerçek dosya/istek süreleri, bellek/sinyal kayıtları ve karşılaştırma JSON'u artifact olur. Core+API runner-dakikası ve yürütme aralığı eş kapsamda karşılaştırılır; hazırlık/kuyruk ve diğer workflow maliyetleri ayrı gösterilir. Devralınan eski başarılı işin zamanları yeniden çalıştırılmış gibi sunulmaz.

Deney hiçbir candidate/main/CD kabul makbuzu veya merge status'u üretmez; üretim CI ve development dağıtımı kendi on iki shard kabul kanıtını kullanır. Ölçüm koşusu bu kanıtın yerine geçmez. Yeni workflow ve CI araçlarının kurulumu mevcut kaynak-özel inceleme/kurulum prosedürüne tabidir; politika muafiyeti eklenmez.

## Cloudflare dağıtımı

[Cloudflare delivery](../.github/workflows/cd-cloudflare.yml), aynı depoda güncel `main` için başarıyla tamamlanmış Main acceptance koşusundan sonra çalışır. Aynı commit, run, güncel attempt ve kaynak kanıtı doğrulanır. Otomatik seçim son başarılı Cloudflare dağıtımından bu yana biriken Vite, UI/API/TypeScript ve workspace build girdisi farkını kullanır. Kabul edilmiş güncel main, run ID ile manuel yeniden seçilebilir.

Vite build, yayın anahtarı bulunmayan ayrı job'da `apps/web/dist` üretir. Uygulama origin'i `https://app.fethiyetango.com`; mevcut Supabase ve public ingress hedefleri [istemci protokolündedir](client-integration.md#statik-spa-transportu). Public `VITE_SUPABASE_PUBLISHABLE_KEY` ve `VITE_TURNSTILE_SITE_KEY` GitHub vars üzerinden sağlanır. Arşiv aynı workflow'da artifact kimliği ve SHA-256 ile bağlanır.

Yazma adımı, yalnız main'e açık `cloudflare-production` GitHub environment'ındaki `CLOUDFLARE_API_TOKEN` ile mevcut `ftksaas-app` Worker'a statik sürüm yükler. Token Cloudflare Workers düzenleme yetkisine kapsamlanır. Cloudflare API'ye her yazma aşaması öncesinde güncel kaynak tekrar doğrulanır. Sürüm kimliği ve commit etiketi doğrulandıktan sonra sürüm %100 trafiğe alınır. Aynı sürümün aktif olduğu Cloudflare API'den, Vite HTML ve giriş modülünün hash eşleşmesi ise yayımlı root/login/callback üzerinden doğrulanır. DNS ve route ayarları bu workflow tarafından yönetilmez.

## Supabase dağıtım seçimi

`Development delivery` kaynak bağlı başarılı backend kabulünü doğruladıktan sonra, son başarılı development teslim makbuzunun kaynak SHA’sı ile güncel kabul edilmiş main’in tam Git ağaçlarını karşılaştırır. Yalnız `apps/backend/supabase/**` içeriği veya bu yolun dosya modu/türü değişmişse deploy seçilir; silme ve taşımanın iki ucu kapsanır. CI, belge veya başka backend kaynakları tek başına deploy seçmez. Üretilmiş Edge çıktısının güncelliği mevcut aday kabulünde korunur; deploy filtresi test/güvenlik kapsamını değiştirmez.

Son başarılı teslim bütün sayfalardan aranır; atlanmış veya başarısız deploy referansı ilerletmez. Böylece önceki başarısız teslimden kalan Supabase farkı sonraki başarılı kabulde yeniden seçilir. Hiç başarılı teslim yoksa ilk deploy seçilir. Son başarılı teslimin makbuzu eksik, expired veya bozuksa ya da tam Git ağacı okunamıyorsa seçim hata verir; eksik kanıt “fark yok” sayılmaz ve eski makbuza geri dönülmez. Manuel çalıştırma da aynı filtreyi kullanır. Workflow tetikleyicileri değişmez; fark yokken `source` çalışır, deploy işi atlanır.

## Güvenilir politika ve dağıtım

`ftksaas/merge-clean` status’unu yalnız main’den çalışan doğrulayıcı üretir. Aday testleri salt-okuma token kullanır, secrets/status-write yetkisi almaz. Yetkili doğrulayıcı aday kodu veya artifact executable’ı çalıştırmaz. Bütün `.github/workflows/*`, `.github/dependabot.yml`, frontend `ci-scope.mjs`/`ci-proof.mjs`, `scripts/ci` ve clean/start/path runner blob/mode kümesi trusted yüzeydir. Frontend-only sınıflandırma dahi workflow politika değişikliğine otomatik izin vermez.

Olağan test geliştirmesi politika kurulumu gerektirmez: `api-suites.json` kaynak/hash/satır aralığı/import ve ölçüm verisi, mevcut test kaynaklarının sahipliğini ve exclusive birimlerini koruyarak genişletilebilir. Sürüm, dedicated runner veya başka politika alanları değişirse koruma sürer. `apps/backend/package.json` içinde yalnız sabit `node --test --test-concurrency=2` komutunun güvenli `tests/*.test.mjs` listesine mevcut kökleri koruyan eklemeler normal kabul yolundadır. Yeni testler mevcut köke import edilebilir veya bağımsız yeni kök olarak envantere alınabilir; komutun kendisi ve diğer script/bağımlılık/manifest alanları politika kontrolünde kalır. Güncel kök listesi tek test envanterinden okunur; eski dört shard süre snapshot’ı yalnız tarihsel kabul/ölçüm içindir ve yeni kök eklenmesini engellemez. Test silme/atlama/assertion azaltma mevcut kalite kontrolünden muaf değildir.

Merge/main doğrulayıcısı test kapsamını ve dondurulmuş shard planını main’in test listesinden değil, kanıtın tam test edilmiş Git ağacından hesaplar. Yalnız güvenilir main araçları adayın package/JSON/test blob’larını veri olarak okur; aday modülü import edilmez veya çalıştırılmaz. Blob hash’i, regular dosya modu, güvenli test yolları, UTF-8/boyut sınırı, tam satır sahipliği, tekil test kimlikleri ve on iki işin gerçek run/attempt başarısı doğrulanır. Eksik/truncated ağaç, yanlış kapsam/plan veya kayıp eski test sahipliği başarısızdır.

Trusted yüzey değişen PR’de bağımsız son kaynak incelemesi, gerçek aday başarısı ve tam kaynağa özel açık kurulum yetkisi gerekir. Önceki PR izinleri taşınmaz. Sahte status, bypass, direct push veya koruma gevşetme yoktur. Required-check/strict-base/bypass ve review düzeninin son doğrulanmış durumu [güncel kabul kaydındadır](../apps/backend/docs/00-FtkSaaS-yeni-sohbet-devir.md); bağımsız ajan incelemesi zorunludur.

CD, başarılı main source/proof job’larını ve dayandığı adayın kanıtını yeniden doğrular. Her yazma öncesi current main/run/attempt ve kaynak eşdeğerliği kontrol edilir. Araya giren yalnız belge/frontend değişimi backend girdilerini değiştirmediyse kabul edilmiş backend dağıtılabilir; shared/backend/bilinmeyen fark bunu reddeder. Belge kanıtı runtime kabulü yerine geçmez. Önceki dağıtım receipt’i yalnız aynı repo güvenilir main CD koşusunun gerçek başarılı aynı-attempt deploy işinden okunur; PR/fork/atlanan deploy makbuzu optimizasyon yetkisi vermez. Hosted Edge kaynak/version/JWT eşleşmesi ayrıca gerekir.

## Ölçüm ve ajan devri

Ölçümlü deterministik shard planı eksik/yeni/mükerrer suite veya geçersiz süreyi reddeder. `refresh-suite-durations.mjs` başarılı aday full-clean (ve tarihsel full-main) job loglarından bilinçli bakım yapar; proof-only main koşusu test ölçümü sayılmaz. Örtüşen process süreleri wall diye toplanmaz; ölçülmemiş hız/maliyet kazancı iddia edilmez. Eski seri reference ölçümleri tarihsel kalır; metadata etiketi yeni otomatik benchmark başlatmaz.

Aday full clean başlayınca run/PR/head/base/tested merge/kuyruk/sonraki adımı bildirip turu bitir. Run henüz listelenmiyorsa workflow ve tetikleme zamanını kaydet; bekleme/polling/log takibi/watch/arka plan otomasyonu yoktur. Kullanıcı dönünce gerçek sonuç ve güncel kaynak bir kez doğrulanır. Sırf durum için çalışan kaynağı değiştirme; kanıt sonraki doğal belge değişikliğinde eşitlenir. Main kanıt kabulü ve gerekli development CD doğrulanmadan teslim kapanmaz.
